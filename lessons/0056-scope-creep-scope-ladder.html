Scope creep and the scope ladder

A session rarely derails in one leap. It climbs a ladder one reasonable step at a time: a question becomes a fix, the fix becomes a product, the product becomes something you publish. This lesson teaches you to see the ladder, and to climb only the rungs you actually choose.

About 15 minutesBuilds on: 4.1 Definition of doneWin: you can name which rung you are on, and stop a climb nobody chose

Why this matters for shipping your app

Your mission is a public app, and lesson 4.1 gave you the tool that protects it: a written definition of done. But a definition of done only works if the work stays the work. The quieter failure is that the work changes while you are inside it. You sit down to answer one question, and you stand up much later holding something nobody asked for, unreviewed and half-understood.

People who study how software grows have a plain warning here. Anthropic's own guidance for building agent systems is to prefer the simplest solution possible, and only increasing complexity when needed[1], and to add complexity only when it demonstrably improves outcomes.[1] This lesson is about noticing the moment complexity gets added — because with an agent, the moment is easy to miss and cheap to repeat.

The ladder

Think of any request to your agent as sitting on one of three rungs.

The scope ladder: three rungs, three different jobs
RungThe question it answersDone meansWhat the next rung whispers
ResearchWhy is this happening? What is true here?The question is answered, in writing. Nothing changed."While you are in there, fix it."
ProductMake the thing work for its user.You ran the result yourself and it held up (Unit 2)."Other people would want this too."
PluginLet someone else install and use the thing.A stranger installs it and it works without you."Now it could also do this other job…"

Each rung is a legitimate place to stand. The trouble is not ambition; it is scope creep: arriving at a rung nobody chose. Each rung is also a different job. Research costs minutes. Product costs the verification habits of Unit 2 — running the thing, checking the real result. Plugin costs documentation, packaging, a public home for the code, and answering people you have never met. Climbing without noticing means inheriting a bill you never read.

One question, twenty hours

A real pattern, anonymized

A user asked an agent one question about a 3-D gallery: why do the wheels on the vehicle models render as invisible? Ninety seconds later the agent had the answer — a transparency setting was treating the wheel textures as see-through. The question was answered. The research rung was done.

Then the user asked for the rendering to match the original program's behavior exactly, then to remove the remaining approximations, then to match a reference implementation byte for byte, then to include effects nobody had mentioned. Roughly twenty hours of work later, the session ended with a huge set of changes and a request for review so large that an automated reviewer skipped it. Every single message along the way was reasonable. The whole path was never chosen by anyone.

Notice what the climb was made of: not one big request, but a chain of small yeses. Each answer defined the next question. Each step up made the next step feel obvious. That is the shape of scope creep with an agent — and the agent will not stop it, because stopping is not its job. Its loop runs until it believes the task is done, and each new message quietly rewrites what the task is.

Research quietly becomes a product

A real pattern, anonymized

A user asked an agent to keep researching whether a design toolkit could produce slide decks. The research produced a note. Then the note suggested a small generator, so the generator got built. Then the generator became a reusable skill, the skill became a whole workflow, and the workflow was packaged and published so that other people could install it — on three different agent tools. Around seventeen hours of work, driven by roughly a dozen short messages from the user, almost every one of them adding "and also".

The published plugin was genuinely good. The failure was upstream of it: no message ever said we are now building a product, so no definition of done was ever written, no budget was set, and nobody decided what would be left out.

Codex's own best-practices page draws exactly this line between the rungs: Keep the first version local while you iterate. When it's ready to share broadly, package it as a plugin.[3] Local and shared are different rungs, and the page treats moving between them as a decision you make — not something that happens on its own.

Name the rung before you press enter

You already know the fix from lesson 4.1: define done. The ladder adds one line to it — which rung is this? Compare two openings for the same afternoon:

Rung unnamed

"Look into why the menu overlaps the header on phones."

Six "and also" messages later, this is a redesign, a new settings screen, and a request to publish — none of them chosen, none of them finished.

Rung named

"Research only: explain why the menu overlaps the header on phones. Do not change any files. Write the cause and the file it lives in, then stop."

One rung, one finish line, and a deliberate decision afterwards about whether to climb.

Codex's guide puts the general form in its prompt template: Done when: What should be true before the task is complete[3] — and says stating it helps Codex stay scoped, make fewer assumptions, and produce work that's easier to review.[3] The same move works in any agent, because it supplies the one thing the loop cannot invent: the boundary.

Rung: research only.
Question to answer: [the one thing you want to know].
Stop when: you can explain the answer in a short paragraph, and name the file it involves.
Do not: change any files, fix anything else you notice, or start the next step.
If a fix looks obvious, write it as a one-line suggestion and stop there.

When you later choose to climb, make the climb its own decision, with its own definition of done:

New rung: make [the one result] work.
Done means: I ran it myself and [the check you will perform].
Still out of scope: publishing, other pages, [the tempting next thing].
When done means is met, stop and report. Do not climb further without asking.

The last line matters because the agent reads requests conservatively. Anthropic's documentation notes that Claude tends to read a request conservatively and build the smallest thing that satisfies it[2] — so the size of the job is telling Claude about scope, which only you know.[2] If you do not say where the top of the ladder is, "done" defaults to whatever the last message implied.

Reading the ladder in the middle of a session

Climbs rarely announce themselves. They arrive as ordinary sentences — usually yours.

Signals that you are climbing a rung you did not choose
You hear yourself sayingWhat it actually meansThe move
"While you are in there, also…"A new deliverable is joining the jobFinish the current rung first, or name the new one as a new task
"It should match the original exactly"The finish line moved from "works" to "perfect"Ask whether anyone needs perfect, or whether "works" was the need
"Other people would want this"You are on the plugin rung without decidingStep back to the product rung until someone actually uses it
"Let's publish it"Packaging costs are about to be inheritedWrite down what publishing will oblige you to maintain, then decide

None of these sentences is wrong. The move is not to forbid them; it is to notice that each one is a promotion, and to make promotions deliberate. Cutting a rung on purpose is a skill of its own — lesson 4.13 teaches how to leave things out cleanly, and lesson 4.3 teaches how to say where work stops.

Recall before you read on

Without scrolling up: what are the three rungs of the scope ladder, and what one sentence do you add to a prompt to keep a climb from starting on its own?

Research (answer a question), product (make it work for its user), plugin (others can install it). The sentence is naming the rung and its stop point — for example "research only; do not change any files; stop when the question is answered."

Do it: hold one rung in your own project

Do it in your own agent

You should see one short answer to your question and no edits on the research pass. On the promotion pass, the agent should stop at your stated check and ask before going further. If the research pass changed files anyway, your tool may be in a mode that auto-approves edits — re-read lesson 0.6 and pick a mode that asks first.

Stopping a climb that already started

Sometimes you notice the climb only when you are two rungs up. All three tools let you stop mid-flight without losing the work; the keys differ.

Press Esc. Anthropic's documentation says: Esc stops Claude mid-action and keeps everything up to that point, so you can redirect without losing work.[2] Then send a rung-named prompt to restart the work at the rung you want.

Codex's quickstart documents Press Ctrl+C or run /exit to close the session[4] — its docs do not name a mid-turn interrupt key, so the reliable way off a climb is to close and start again with a rung-named prompt. Work you committed (lesson 3.13) survives.

Press Esc: the keybindings page lists it as Dismiss autocomplete or interrupt the active operation.[5] Then send a rung-named prompt to restart at the rung you chose.

omp is documented only by its own authors, so check anything surprising against omp.sh/docs or with your teacher. The other two vendors document themselves as well — treat every tool's docs as the final word on its keys.

Check yourself

Question 1 of 3

Which request sits on the research rung?

Research answers a question and changes nothing. The others are the product rung (rebuild, ship) and the plugin rung (publish).

Question 2 of 3

The agent offers to fix something extra it noticed. You do not need it. What is the ladder-safe reply?

"Quick" is not a rung; it is how climbs start. Record the suggestion for later and finish the rung you chose — lesson 4.13 shows how to leave it cleanly.

Question 3 of 3

Which sentence signals a climb that nobody has decided on?

"While you are there" adds a second deliverable to a job already in progress. The other three name a stop point, a definition of done, and a research boundary.

Ask your teacher

Try asking your agent about its own session: "Which rung of the ladder are we on right now — research, product, or plugin? Answer in one sentence, then stop." Asking the agent to place the work is itself a scope check.
