The terminal in five commands

The terminal is the room your agent works in. Five commands are enough to walk into the right folder, see what is there, open it, and start something — and to fix things when the agent says a file exists that you cannot find.

Why this matters for shipping your app

Everything later in this course happens in a working directory: the folder a program is currently standing in. When you start a coding agent, it takes its bearings from the folder you started it in. Start it one level too high and it treats your whole home folder as the project; start it inside the wrong copy and it edits a file you are not looking at.

You do not need to become a command-line user. You need enough to answer one question reliably — which folder am I in, and what is in it? — because that explains most of the confusing moments of the first week: a file that "does not exist", a page that will not load, an agent that changed the wrong thing.

A terminal is a place to type

On a Mac, press Cmd + Space, type Terminal, and press Enter. Anthropic's guide for first-time users describes what appears: A window will appear with a blinking cursor. This is your terminal, where you type commands.[1]

A shell is the program inside that window that reads your line, runs it, and prints what came back. You type a command, press Enter, read the result, and type the next one. That is the whole interaction; there is nothing to click.

Two words, one thing: the window is the terminal; the program reading your typing is the shell. This course says "terminal" for both unless the difference matters.

1. Where am I? pwd

pwd stands for "print working directory". Its manual page says it writes the absolute pathname of the current working directory to the standard output.[2] In plain words: it prints the full address of the folder you are standing in, starting from the top of the disk.

my-app % pwd
/Volumes/Work/my-app

The % and everything left of it is the prompt: the shell telling you it is ready for a line. You do not type it. Everything to the right on that first line is what you typed; the line below is the answer. Prompts are configurable, so yours may look different from this one.

Your path will differ too: this example lives on an external drive. The point of pwd is that it prints the whole path, not a shortened one.

2. What is here? ls

ls lists a folder's contents. The manual says that for a folder, ls displays the names of files contained within that directory, and that with no folder named it lists the one you are already in.[3]

my-app % ls
index.html    notes    style.css

Two details matter immediately. First, plain ls hides names that begin with a dot: the macOS manual says -a is what adds entries whose names begin with a dot.[3] Settings files and project metadata often start with a dot, so a folder can look nearly empty while holding plenty. Second, ls shows names, not contents: seeing index.html in the list tells you the file is there, not what it says.

To see hidden entries too, run ls -a. You can also name a folder: ls notes looks inside it without moving you.

3. Go there: cd

cd changes the working directory. Bash's manual says: Change the current working directory to directory, and if you give it no folder at all, the value of the HOME shell variable is used.[4] So cd alone takes you home, and cd with a name takes you into that folder:

my-app % cd notes
notes % pwd
/Volumes/Work/my-app/notes
notes % cd ..
my-app %

.. means "the folder above this one". Your prompt changes when you move, so run pwd whenever you are unsure — it is cheap and it never lies.

The error you will meet most

A wrong folder name gives a short error and leaves you where you were. On this Mac, cd nonexistent-folder prints zsh:cd:1: no such file or directory: nonexistent-folder. The shell did not move. A failed cd never drops you somewhere unexpected, so try again.

4. Show me: open

open hands a file or folder to the program your Mac associates with it. Its manual page says it opens a file (or a directory or URL), just as if you had double-clicked the file's icon.[5] A single dot means "this folder", so this is the command that turns a path you typed into a window you can look at:

my-app % open .
my-app % open index.html

The first line opens the folder in Finder. The second opens the page in your browser — often the fastest way to check that a file the agent edited is the file you think it is. open is a macOS command; other systems have their own equivalent.

5. Run something: a name, then Enter

The fifth command is a habit: run a program by typing its name. Most programs finish and give you the prompt back. Some keep running: a server, a watcher, a live view. You will meet those constantly, because that is how a project is started.

Project folders often carry a list of named commands. A web project may be started by a line such as npm run dev; npm's manual gives the shape as npm run <command> [-- <args>] and says it runs an arbitrary command from a package's "scripts" object.[6] The name after npm run is a nickname the project defined, not a program installed on your Mac.

The rule to remember: while a program is running in the foreground, the prompt does not come back. That is not necessarily a freeze. Ctrl + C asks the running program to stop by sending an interrupt; Bash's manual describes keyboard-generated signals such as SIGINT, usually generated by Ctrl + C.[7] A program can handle that request differently, so check that your prompt returns.

my-app % top
Processes: 989 total, 3 running, 765 sleeping
...
q
my-app %

top is the macOS tool that periodically displays a sorted list of system processes; its manual adds that q means Quit.[8] It is safe to try: unless you press other keys, it only displays. Press q, and your prompt returns.

Recall before you read on

Without scrolling up: which command tells you where you are, which one shows what is beside you, and which one moves you? What does an empty prompt mean?

pwd prints the working directory; ls lists what is in it; cd moves you. open . shows the folder in Finder. A prompt with nothing running means the last program has ended and the shell is ready for the next line — if you expected one to keep going, it stopped, perhaps because it failed.

A session, start to finish

Here is a real sequence, edited only to use a made-up path. Read the prompt as well as the output; the prompt is evidence of where you are.

youpwd
tool/Volumes/Work/my-app
youls
toolindex.html notes style.css
youcd notes
youls
tooltodo.txt
youcd ..
youopen .
noteYou asked for the folder, not the page. Finder opens; nothing appears in the terminal.

Notice what is missing: no confirmation messages. In this example, cd and open print nothing when they succeed. Silence alone is not proof of success; checking with pwd and looking at the opened folder beats watching for a "done" line.

A real pattern, anonymized

A user asked an agent to copy the newest download into a project. The agent's first listing command failed, even though the folder plainly existed. The user's shell had a shortcut named ls pointing at a different tool that did not behave like the standard one. The agent read the error, retried with /bin/ls, and the listing came back correct.

Two habits follow. If a command's output does not look like what its name promises, suspect the environment before the project. And an agent with a terminal can diagnose this itself, if it reads the output instead of assuming the command worked.

Your turn

What you should see: the same path after step 4's pwd as the folder you meant; a Finder window showing exactly the names from ls; and, after top, your own prompt again, ready for a line. If the Finder window shows a different set of files, you are not where you think you are — run pwd and compare it with the window's title bar.

Start your agent from the right folder

All three agents start from the folder you launch them in. The installation lesson comes next; these are the command names you will use once installed. Before using an agent, follow 0.6 Approvals and permissions to keep approval prompts on rather than relying on its starting settings.

Move into the project folder with cd, then type claude and press Enter. Its terminal guide adds two facts worth knowing now: You can't click on things in the terminal, and Esc interrupts the agent while it is working.[1]

OpenAI's CLI page gives the step in one line: Open a project directory and run codex.[9] "Open a project directory" means cd into it first. The first run asks you to sign in.

The omp docs show the pattern as two lines, cd my-project then omp, and describe it plainly: Bare omp opens the interactive terminal UI.[10] Its documentation comes only from its own authors.

If the agent's first message mentions a folder you did not expect, stop and run pwd. It is almost always the working directory, not the agent.

Check yourself

Question 1 of 3

A command finishes and your prompt appears again. What does that mean?

The prompt means the foreground program has ended and the shell is waiting. Success and failure both return a prompt; the printed output, not the prompt's return, tells you which happened.

Question 2 of 3

You run ls and it prints nothing at all. What is the best reading?

An empty listing can mean the folder is empty, or that everything in it starts with a dot and is hidden from plain ls. Either way the command ran; check with pwd and ls -a.

Question 3 of 3

An agent says it created a file, but you cannot find it. What should you check first?

The file exists somewhere; the usual reason you cannot see it is that your agent, or your Finder window, is looking at a different working directory. Run pwd in the agent's session and in yours.
