Install and sign in

Two one-time jobs stand between you and your first prompt: put the program where your terminal can find it, then prove which account pays for the work. After that, launching is one word.

About 15 minutesBuilds on: 0.4 The terminal in five commandsWin: you can start your agent from any project folder

Why this matters for shipping your app

Everything later in this course happens inside an agent session: the first page, the save points, the deploy. If the agent is not installed and signed in, none of it can start. Treat this as a reference page: run the steps for your agent, keep it nearby, and return when a new machine or a reinstall needs the same commands.

Two different one-time jobs

Installing copies a program onto your computer. Signing in tells the company behind that program which account you are, so the work can be billed to you. They fail differently, which is why this lesson keeps them apart.

When you type a command name such as claude, your terminal does not search the whole disk. It looks through a fixed list of folders called the PATH. An install that leaves the program outside those folders looks successful and still answers command not found. That explains most first-day setup confusion.

The order that avoids trouble

Install, open a new terminal window, check the version, then start the agent once to sign in. Two of the three vendors explicitly tell you to open a new terminal window for the check; an already-open window keeps the search list it started with.[1][4]

Step 1: install and check

Pick the tab for your agent. Each command below is the vendor's own documented macOS/Linux installer, copied verbatim from the page cited beside it. Run it in a terminal, from any folder. You do not need to be inside a project yet.

curl -fsSL https://claude.ai/install.sh | bash

Anthropic labels this the Native Install (Recommended).[1] Homebrew users can run brew install --cask claude-code instead, but Homebrew installs do not update themselves.[1] Then check it from a new window:

claude --version

The docs say: The command prints a version number followed by (Claude Code).[1]

curl -fsSL https://chatgpt.com/codex/install.sh | sh

OpenAI's documented standalone installer for macOS and Linux; npm install -g @openai/codex and brew install --cask codex are listed as alternatives.[3] Then check it:

codex --version

You should see a line beginning codex-cli followed by a version number. Open a new window first if the old one says the command is missing.

curl -fsSL https://omp.sh/install | sh

omp's own install script. It is a shell script fetched from the project's site, so you are running code the project publishes.[4] Then check it:

omp --version

The quickstart says: If your shell cannot find omp, follow the PATH instruction printed by the installer, then open a new terminal and try again.[4]

If the check prints "command not found"

Nothing is broken. The program is on your disk but not in a folder your terminal searches. Anthropic's quickstart names the cause directly: the install directory isn't on your PATH yet.[1] Close the terminal window, open a fresh one, and run the check again. If that does not help, the installer usually printed a line telling you which folder to add; copy that line into your shell's startup file as it instructs, then open another new window. Do not retype the install command repeatedly; it will not fix a PATH problem.

Step 2: sign in

Signing in happens the first time you launch the agent, not during the install. Launch it from a project folder so the first session also proves the folder part works. Any folder will do for now; 0.3 explains why the launch folder matters.

Run claude in the folder. Claude Code prompts you to log in on first use.[1] It opens a browser window; finish there and return to the terminal. Once you are through, your credentials are stored and you won't need to log in again.[1] To switch accounts later, type /login in a session; to sign out, type /logout.[2]

Run codex in the folder. The first time you run Codex, choose Sign in with ChatGPT or another available sign-in method.[3] Follow the prompts it shows, then return to the terminal. To remove the stored credential later, codex logout is the documented command.[5]

Run omp in the folder. The first launch opens a setup wizard.[4] Keep the Sign in tab, choose your provider, press Enter, and finish in the browser. Then choose a default model and accept the remaining appearance prompts. OAuth users can reopen sign-in with /login.[4]

Do not paste credentials into the chat

If a sign-in flow asks for a code or an API key, type it into the prompt that asks for it, never into a message to the agent. omp's own security page warns that authorization URLs, callback URLs, device codes and pasted login codes should be treated as secrets until the login finishes.[6] The same habit protects you with any tool.

What first launch may also ask

First launch can also touch permissions. Each agent applies a default permission mode, and any prompt you see about allowing an action belongs to that topic, not to installation. For now, choose the option that keeps approval prompts on. Lesson 0.6 explains each choice; you can change it later without reinstalling.

Recall before you read on

Without scrolling up: what are the two one-time jobs in this lesson, and which command proves the first one worked?

Install (put the program where the terminal can find it) and sign in (connect it to your account). The check is the version command — claude --version, codex --version or omp --version — run in a new terminal window.

Where the credentials live, and how to undo it

Signing in stores a credential on your computer so later sessions start without a browser. That is convenient and it is also the reason to sign out on a shared machine.

AgentSign out laterWhat the docs say about storage
Claude Code/logoutCredentials are stored; you won't need to log in again.[2]
Codexcodex logoutRemove stored authentication credentials.[5]
omp/logoutThe local database is not encrypted at rest.[6]

On a shared or borrowed computer, a stored login is only as private as that machine's own account.

Do it now

You should see a version number, then a prompt that names your project folder, then an answer that names the same folder. If instead you see command not found, you are in the wrong window or the installer's PATH line has not been applied yet; repeat step 2 in a fresh window before anything else.

Check yourself

Question 1 of 3

The install command finishes, but the version check says "command not found". What is the likely cause?

Install and PATH are separate. The program is on disk; the terminal simply has not been told where to look. A new window, and the installer's PATH line, fixes it.

Question 2 of 3

What does signing in actually do on first launch?

Sign-in is about identity and billing, and it saves a credential so later sessions start without a browser. It does not upload your folder or change what the agent may do.

Question 3 of 3

You are about to use an agent on a shared computer. What should you do before leaving?

The credential sits on the machine between sessions. Signing out removes it; neither reinstalling nor deleting a project does that job.
