Let the agent schedule the work

For big tasks you stop typing the steps and start handing over goals with a finish line. The agent becomes the scheduler. And when your prompting feels off, you can ask the agent to critique it — that is a meta-prompt.

Why this matters for shipping your app

Unit 1 taught you to size a prompt to one outcome you can check (lesson 1.13). Real apps are bigger than one outcome. The new question is not "how small should this prompt be" but "who keeps the order of the work?" For anything larger than a single sitting, the answer is: let the agent schedule.

One goal in, a schedule out

When you treat the agent as a scheduler, you stop naming steps. You hand over four things: the goal, the context it needs, the boundaries, and what "done" looks like. The agent then decides what to read first, what to change, what to check, and in what order — and it may hand pieces to helper agents (subagents, lesson 5.4) that work in parallel, like the swarm in lesson 9.5.

Anthropic's prompting guide describes this directly: the latest models orchestrate subagents natively and recognize when tasks would benefit from delegating work to specialized subagents and do so proactively without requiring explicit instruction.[1] Anthropic's engineering essay draws the line you are crossing: Workflows are systems where LLMs and tools are orchestrated through predefined code paths, while agents are LLMs using tools based on environmental feedback in a loop.[2] When you type the steps one by one, you are the predefined code path. When you hand over a goal, the agent runs the loop.

A real pattern, anonymized

A user had a written roadmap of more than eighty small items and sent the agent a single line: implement the roadmap — plus one guardrail sentence naming exactly which items to stop at. The agent read the plan, split the work, and ran several helpers in parallel on separate copies of the project, merging each piece as it finished. Because the finish line was named, the run ended instead of sprawling. Hours later the same user asked the agent to critique their own prompting. The honest answer: they had been acting as project manager between every step, and would get further by handing over one bigger deliverable — for example "deliver a review-ready change, own the sequencing and cleanup, and stop before merging" — instead of a series of instructions.

What the scheduler is doing while you wait

Behind the scenes the agent still runs a loop, not a straight line. Anthropic's description of its coding agent names three phases: it works through three phases: gather context, take action, and verify results.[4] When it schedules, it decides how many times to repeat that loop and what to read before each pass. You can see the phases in the transcript: reads first, then edits, then a test or a diff.

That is also where a bad plan shows up. If the agent keeps gathering and never acts, the context line was too broad. If it edits before it reads, the goal was too vague to check. Both are prompt problems you can fix in the next message.

The scheduler still needs a finish line

Scheduling only works with a stop condition (lesson 4.3). "Implement the roadmap" with no finish line means "work until nothing is left", which never happens. Codex's best-practices page frames the same shape as four lines: Goal: what are you trying to change or build, Context: which files and facts matter, Constraints: what it must follow, Done when: what must be true before it is complete.[3] A scheduled task is an outcome-sized prompt whose outcome happens to be large — the four lines still decide whether it ever stops.

The division of labour

You own the goal, the boundaries and the finish line. The agent owns the sequence, the splitting and the checking. If you find yourself naming files again mid-task, you have slipped back into scheduling — rewrite the next message as a result instead.

Keep steering, not scheduling

Handing over the sequence does not mean walking away. omp's own docs put the human role plainly: Intervene when needed. Send a steering message while it works, answer a question, or reject an unsafe action.[5] The difference is what your message contains. "Change the error text and then run the tests" is scheduling. "The empty state looks wrong; the fix should keep the existing button styling" is steering: you name the constraint and leave the order to the agent.

Meta-prompting: critique how you prompt

A meta-prompt is a prompt about your prompts. You paste your own recent messages — or describe your habit — and ask the agent what is costing you time. Anthropic's guide endorses the same review habit on the agent's side: the common pattern is to generate a draft, review it against criteria, then refine based on the review, and to regularly self-critique your approach and plan.[1] Pointing that loop at yourself is the meta-prompt: the agent reviews your instructions the way it would review its own draft.

The critique is advice, not a verdict

Like a second reviewer's report (lesson 2.10), the critique is advisory. Agents can flatter, so ask for concrete, session-specific changes — not praise. You decide which habits to keep; product intent is yours (lesson 1.6).

Recall before you read on

Without scrolling up: what are the four things you hand over when the agent acts as scheduler? And in one sentence, what is a meta-prompt?

Goal, context, constraints, and done-when (the finish line). A meta-prompt is a prompt about your prompting — you ask the agent to critique how you have been asking, and to suggest concrete changes.

A meta-prompt you can paste

Send this at the end of any session where the prompting felt clumsy. It changes nothing in your files.

Look at this session. Critique how I have been prompting you:
which of my messages were step-by-step instructions I should have
handed over as one bigger outcome, and which were too vague to act on?
Give me three concrete changes I can make in my next prompt.
Quote my own words where you can. Do not change any files.

Read the answer as a report, then choose. If the agent says "hand over bigger outcomes", test that once on a real task before changing your habits everywhere.

Do it: run a meta-prompt on your own session

Do it in your own agent

You should see the agent quote or paraphrase your own earlier messages and name specific habits — for example that you listed steps, or that you never said what done meant. Expect it to suggest handing over a bigger outcome with a written finish line. If it only gives generic praise, ask again with "quote my own words where you can".

Check yourself

Question 1 of 3

You hand the agent a big goal with a written finish line. What does "the agent as scheduler" mean?

The agent decides the sequence, splitting and checking itself. Typing the steps yourself is the opposite — that makes you the scheduler.

Question 2 of 3

Which of these is a meta-prompt?

A meta-prompt's subject is your prompting — you ask the agent to review how you have been asking. Length and delivery channel have nothing to do with it.

Question 3 of 3

A meta-prompt tells you that you micro-manage: nine messages, one step each. What is the best move?

The critique is advisory: test its suggestion once by handing over one bigger outcome with a finish line. Ignoring it or quitting both waste what the critique is for.

Ask your teacher
