Desktop apps vs the terminal: buttons, cards, and checklists

The same agent can live in a window full of clickable controls or in a terminal where you type everything. The loop underneath is identical; only the surface changes. Knowing both lets you pick the right one for the moment.

Why this matters for shipping

Your mission is to ship an app by directing an agent, and you will direct it many times a day. Lesson 0.2 introduced the three agents; each of them can appear in more than one shell. Claude Code runs in the terminal and in a desktop app. Codex runs in the terminal and inside the ChatGPT desktop app. omp runs in the terminal. Choosing the shell is not about power — the agent underneath is the same — it is about how you prefer to steer, approve, and watch the work.

Same agent, two surfaces

In the terminal, everything is text: you type a prompt, the agent types back, and approvals arrive as questions you answer by typing. In a desktop app, the same session is drawn as a window: a prompt box, a list of sessions, diffs you can scroll, and buttons for common replies. Anthropic's desktop documentation describes the Code tab directly: launch Claude, sign in, and click the Code tab, where the sidebar lists your sessions and lets you run several in parallel.[1]

None of this changes what the agent can do. The read-act-verify loop from lesson 0.1 runs exactly the same. What changes is how you interact with it: clicking instead of typing.

What a desktop app adds

Desktop apps turn frequent actions into visible controls. In Claude Code's desktop app, for example, you can click the stop button to interrupt immediately, attach files via the + button next to the prompt box, and accept a suggested next prompt that the app offers in gray text.[1] When the agent needs a decision, a permission card appears and Claude waits for your choice: Allow once, Always allow, or Deny.[1] When work is ready to publish, a changes card shows the pull request with its CI status and lets you turn on Auto-fix or Merge when ready.[1]

The diff view is the clearest example of this difference. After the agent edits your code, the diff view lets you review modifications file by file before creating a pull request.[1] In the terminal you get the same information from git diff, one screenful at a time. Neither view changes the code; both let you check it before anyone else sees it.

A real pattern, anonymized

A user finished a task in a desktop app and the agent ended with a button reading "Commit and open the pull request?" One click sent that exact reply, and the agent committed, pushed, and opened the pull request. In another session, a "Fix the two compile errors" button did the same thing with one click instead of a typed sentence. In a third, the user flipped an Auto-fix toggle and the app woke the agent whenever a review comment arrived — no polling, no typing. The work was identical to what the terminal does; only the clicking differed.

The plan checklist lives in both shells

One feature beginners often miss is the agent's own to-do list. In the terminal, Claude Code's interactive-mode docs define it plainly: The task list is Claude's to-do checklist: items Claude created to plan multi-step work, with indicators showing what's pending, in progress, or complete — toggled with Ctrl+T.[2] A desktop app shows the same plan visually, and its Plan mode lets you approve the approach before any edit: Start complex tasks in Plan so Claude maps out an approach before making changes. Once you approve the plan, switch to Accept edits or Manual to execute it.[1] So the checklist is not a desktop-only luxury; if you live in the terminal, Ctrl+T is the same window.

Recall before you read on

Without scrolling up: name two things a desktop app turns into clickable controls that you would otherwise type in the terminal, and one feature that exists in both shells.

Clickable examples: the stop button, the + attachments button, permission-card choices (Allow once / Always allow / Deny), Auto-fix or Merge-when-ready toggles, and canned reply buttons like "Commit and open the PR?". The plan checklist exists in both: Ctrl+T in the terminal, shown visually in a desktop app.

What each of the three agents offers

Terminal (claude) and a desktop app: launch Claude, sign in, and click the Code tab. The desktop adds the sidebar, browser pane, diff view, cards, and buttons described above.[1]

Terminal (codex) and the ChatGPT desktop app: the app docs say you Choose ChatGPT or Codex after signing in.[3] In the terminal, approvals and questions are answered by typing.

Terminal only in this course: its quickstart has you cd into the project and run omp. Sessions, resume pickers, and approvals all happen as typed commands like omp --resume.[4] Single-vendor docs — check anything surprising with your teacher.

Desktop app or terminal? A field guide

Use the desktop app when

You want to run several sessions side by side, review diffs by scrolling, click approval cards, watch CI on a card, or let Auto-fix react to review comments while you do something else.

Use the terminal when

You are scripting, working over a remote connection, following a guide that says "type this", or you prefer typing. Every approval is a typed answer, and Ctrl+T still shows the checklist.

The honest summary: the desktop app adds convenience and visibility, not capability. If a desktop-only button confuses you, the same action always exists as words you can type — and if a terminal command feels obscure, the desktop app usually has a button for it. You can also switch shells between sessions; omp's docs note sessions are recorded per folder, so omp --resume brings the same work back in the terminal.[4]

The habit

When the agent asks you something — in a card or in text — answer the question, not the format. A button is a pre-typed reply, nothing more. Keep approval prompts on either surface (lesson 0.6).

Check yourself

Question 1 of 4

In a desktop app, the agent shows a "Commit and open a PR?" button. What does clicking it do?

A button in a desktop app is a pre-typed reply. One click sends exactly the words on the button, just as if you had typed them in the terminal.

Question 2 of 4

Which of these does a desktop app add that the terminal lacks?

The desktop doc says the sidebar lists sessions and lets you run several in parallel — a visible layout the text-only terminal does not have. The agent's capabilities are otherwise the same.

Question 3 of 4

Where can you see the agent's to-do checklist for a multi-step task?

The task list is the same checklist in both shells: Ctrl+T toggles it in the terminal, and a desktop app displays it as part of the window.

Question 4 of 4

You are in the terminal and the agent asks "Merge now, or wait?" What do you do?

Terminal approvals are typed answers. The desktop app's buttons are just pre-typed versions of the same replies, so both shells can answer any question.
