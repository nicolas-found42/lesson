Why this is the first real thing to learn

Your mission ends with a public app. Every step between here and there happens inside one folder on your computer: the page, the styles, the pictures, the notes, and later the record of every change you made. When you ask an agent to build something, it reads and writes files in that folder. If you do not know where the folder is, you cannot check what the agent did, and you cannot tell it where to look when it gets lost.

This lesson is short and physical. You will make a folder, put a text file in it, open the file in a browser, and see the whole app-to-be sitting in one place.

A project is a folder, and folders nest

A project folder is an ordinary folder, the same kind you already make to hold photos or tax papers. It has a name you choose. Inside it are files, and inside it you can make more folders. Nothing about it is special to the agent; it is special because that is the thing you point the agent at.

To talk about a file, you give its file path: the route from a starting point down to the file. MDN puts it plainly: To reference one file from another, you have to provide a file path — basically a route, so one file knows where another one is.[1] In the picture above, one path to the picture is my-app/images/cover.jpg. Read it left to right, entering each folder in turn.

The same idea in your file manager is a series of windows: open my-app, open images, there is the picture. Paths matter later because the page will use them to find its own pictures and other pages.

Files are text (most of the ones you will touch)

Open index.html in a plain text editor and you see characters: letters, angle brackets, spaces, line breaks. That is the whole file. A web page is text that a browser knows how to read. MDN says of the .html ending that it identifies the type of file we are dealing with and tells the computer what kind of content it can expect in the file, which program it should use to open the file.[1]

That last part is the file extension: the bit after the last dot in the name. It is a label, not magic. notes.txt and index.html are both plain text; the label tells your computer that one is a note and the other should open in a browser. A photo such as cover.jpg is different: it is binary, not readable as text, and you leave it alone. The code you and the agent write is text you can open, read, search and compare.

Why this is good news

Because the app is text in a folder, it can be copied, backed up, compared line by line, and undone. Everything in Unit 3 about save points rests on this plain fact.

An editor does not invent a second copy of your project. MDN notes, after you open a folder in an editor, that VS Code is using the underlying OS file system, not using some weird file system of its own.[1] The same is true of every editor you might use: it is a window onto the same folder.

The working directory: where the agent is standing

When you start an agent, you start it in one folder. That folder is its working directory: the place it treats as "here" for the whole session. Relative names resolve from there, and the files beneath it are the ones it treats as part of the project.

This is not a technicality. Codex's documentation says to Open a project directory and run codex.[2] Anthropic's memory documentation says project instruction files are loaded from your current working directory and every directory above it — the starting folder decides what the agent picks up at launch.[3] omp keeps its session tied to the same place: omp records completed messages and tool activity in a session associated with the working directory.[4]

You start claude from inside your project folder, after moving there in a terminal.[5] Its project instructions are read from that folder and the folders above it.[3] Lesson 0.4 shows the move; lesson 0.5 covers install and sign-in.

Codex's own instruction is the shortest version of the rule: Open a project directory and run codex.[2] OpenAI's sandbox documentation describes Codex editing within the workspace, and that workspace is the project you opened.[7]

omp ties a session to the working directory it was started in, so the folder you launch from is the folder the conversation belongs to.[4] Start it somewhere else and you are in a different session with a different "here".

Two words you will hear for a place on disk: absolute and relative. An absolute path starts from the top of your computer and always means the same place. A relative path is measured from where you are; as MDN writes, omitting the leading slash makes the path relative to your present working directory.[6] That is why "open index.html" is a complete instruction only when both of you agree on the "here".

Two times the folder was the whole bug

A real pattern, anonymized

A user asked an agent to apply two files she had saved for it in a folder. The agent's first listing of that folder came back empty. Instead of inventing work, it searched the disk, found both files in a neighbouring folder, said what had happened, and only then continued. Nothing was wrong with the files or with the request. The listing and the location did not agree, and one extra look settled it.

A real pattern, anonymized

A different user asked for the contents of their most recent download to be added to a catalogue. The download existed twice: as a compressed file and as the folder it had been unpacked into. Before copying anything, the agent compared the two, confirmed they matched, and worked from the folder. Same bytes, two shapes; knowing which shape is the project mattered.

Both stories are about the same thing. The agent is reliable about the folder it was given. When the folder and the description disagree, every name it tries can point at nothing, and the turn is spent finding out where the files really are.

Recall before you read on

Without scrolling up: what is a working directory, and why does the folder you start the agent in change what it can find? Answer in two sentences.

The working directory is the folder an agent treats as its current place: relative names resolve from it, and the project files beneath it are the ones it works with. Starting in a different folder means a different set of files, a different "here", and often a different session.

Name things so the path stays boring

Filenames become part of paths, and paths later become web addresses. MDN recommends writing your folder and file names in lowercase with no spaces and with words separated by hyphens.[1] So my-app and cover-photo.jpg, not My App or cover photo.jpg. A space in a filename has to be quoted or escaped in many tools, and some tools treat it as two separate names.

The extension is the other half of the name. Keep it, and keep it correct: .html for a page, .css for styles, .js for scripts, .txt for notes. MDN warns that Removing or changing the file extension is likely to cause errors.[1] If a file is called index.html.txt, your browser will show you text instead of a page, and you will spend an evening on it.

Check the name, not the icon

Some systems hide extensions by default, so a file that looks like index.html may really be index.html.txt. Ask your file manager to show full names before you trust one. This is the single most common beginner file problem.

Do it now: build the folder by hand

You now have a folder containing one text file, and that file opens as a page in your browser. You built a (very plain) web page without installing anything, because a page is a text file with an .html name. Note the path you just used: that is the shape of every project you will make in this course.

When you do have an agent running, the sentence to practise is a location sentence, not a task sentence. Try this one the first time you open a session:

Before you change anything: tell me which folder you are working in, list the files you can see there, and say which one you think is the page. Do not edit anything yet.

If the answer names a folder you did not expect, stop and fix the start. That is cheaper than fixing the work.

Check yourself

Question 1 of 3

What does the folder you start your agent in decide?

The starting folder is the working directory: relative names resolve there and the project files beneath it are the ones the agent works with. Cost, model and publishing are separate settings.

Question 2 of 3

The file is named index.html. What does the ending tell your computer?

The extension is a label for the kind of content and the program that should open it. It does not fix the folder, the size or the author.

Question 3 of 3

You name a page my page.html. What is likely to go wrong?

A space splits a name into two arguments for many tools and must be quoted or escaped; some systems also encode it awkwardly in a web address. Lowercase words joined by hyphens avoid the whole class of problems.
