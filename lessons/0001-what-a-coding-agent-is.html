What a coding agent actually is

A chat can only talk. An agent can look at your files, run things, and check what happened. Everything else in this course builds on that difference.

About 15 minutesNeeds: nothingWin: you can tell an agent's work from its claims

Why start here

Your mission is to take an idea to a public app by directing a coding agent. You will do that well only if you hold the right picture of what the agent is doing while you wait. With the wrong picture you will trust it when you shouldn't, and interrupt it when you needn't.

A chat talks. An agent acts.

A plain AI chat takes your message and sends back text. A coding agent is the same kind of AI, but it is also allowed to use tools: read a file, change a file, run a command on your computer. Anthropic's documentation puts it bluntly: Tools are what make Claude Code agentic. Without tools, Claude can only respond with text.[1]

Anthropic's older essay defines agents as typically just LLMs using tools based on environmental feedback in a loop. It carries a note that its tooling details are dated, but this core definition still holds.[2]

That is the whole idea. The model supplies the judgement. The tools let that judgement touch the real world, which in your case means a folder of files that will become your app.

The loop

When you give a task, the agent doesn't answer once. It cycles. Claude Code's documentation names three phases: gather context, take action, and verify results.[1] After each tool use, information feeds back into the loop, informing Claude's next decision.[1]

One message, many tool calls

This is the part that surprises beginners. You type one message. The agent may then make dozens of tool calls before it speaks again.

A real pattern, anonymized

A user asked an agent to put their photo-and-model gallery online so non-technical friends could open it, and to put the link in the project's front page. That was one message. In about sixteen minutes the agent made roughly fifty-five tool calls. It checked how big the project was, found it was too large for the free host, changed its plan so only the small part was published, ran the project's checks, opened the finished page in a real browser, and only then wrote the link where the user had asked.

A simplified picture of that run:

you      "Put my gallery online for my friends."
agent    read   project files, size of everything     (gather)
agent    run    a command to measure folder size      (gather)
agent    edit   publish only the small part           (act)
agent    run    the project's checks                  (verify)
agent    run    open the live page in a browser       (verify)
agent    edit   add the link to the front page        (act)
agent    says   "Done. Here is the link."

Only the first and last lines are a conversation. Everything between is the loop.

Recall before you read on

Without scrolling up: what are the three phases of the loop, and what makes an agent different from a plain chat? Write it in your own words.

Gather context (read, look around), act (edit files, run commands), verify (check whether it worked), repeating until done. An agent differs from a chat because it can use tools, and what those tools return feeds its next decision.

Three tools, one shape

This course covers three agents. They look different but all run the same loop. You start each one from inside a project folder; the next lessons cover folders, the terminal and installation.

Made by Anthropic. Its overview says it helps you build features, fix bugs, and automate development tasks.[3] You start it by typing claude in your project folder.[4]

Made by OpenAI. It can inspect code, make changes, run commands, and automate repeatable work without leaving your terminal.[5] You start it by typing codex in your project folder. It also lives inside the ChatGPT desktop app.[5]

An independent open-source agent from Stencil Labs, describing itself as a coding agent with the IDE wired in.[6] You start it by typing omp in your project folder.[7] Its documentation comes only from its own authors, so check anything surprising with your teacher.

Your choice of tab is remembered, so later lessons show your agent first.

"Done" is a claim, not a proof

Because the loop ends when the agent believes the task is finished, "done" is a statement about what it believes. Claude Code's own best-practices page admits the common failure: Claude said it was done and it wasn't quite, usually because it had no way to check its own work.[8]

The habit this whole course builds

Treat the agent's report as a claim. Look at the real result yourself, and give the agent a way to check its own work. Unit 2 teaches how.

Check yourself

Question 1 of 3

You send one message to a coding agent. What usually happens next?

The agent loops through tools (reading, editing, running) and only then reports back. One message can mean dozens of tool calls.

Question 2 of 3

What is the main difference between an agent and a plain chat?

Tools plus feedback from what they return is what makes it agentic. Speed and approval prompts are separate matters (lesson 0.6 covers approvals).

Question 3 of 3

The agent ends with "Done!" What is the best next move?

"Done" reports what the agent believes. Checking the real result is your job, and the agent can help by running checks too.
