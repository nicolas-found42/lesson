Skills, slash commands and @-mentions

You will type the same instructions again and again: how to check a page, how to review a change, how to write a release note. A skill saves that procedure once, under a name. This lesson shows what those packs are, how to start one, and how to point the agent at a file.

About 15 minutesBuilds on: Lesson 0.1Win: you can load a saved procedure by name and attach a file on purpose

Why this matters for shipping

Explaining a procedure from scratch each time costs attention and gives a slightly different result. Anthropic's skill page names the trigger: create one when you keep pasting the same instructions, checklist, or multi-step procedure into chat.[1] OpenAI says skills reduce the need to paste the same prompt, template, requirements, or process into every chat.[2]

For you, twenty minutes spent teaching an agent how your pages get checked is paid back on every later change.

A skill is a folder with a short file

The name is grander than the thing. A skill is a folder holding a file called SKILL.md, plus any templates or scripts the procedure needs. The file has two parts: a short header saying when the skill applies, and the instructions the agent follows when it does.[1][3]

The header is the only part always visible. Codex starts with each skill's name and description, then loads the full SKILL.md instructions when they decide to use that skill.[3] Anthropic: a skill's body loads only when it's used.[1] A long checklist can sit unused in your project and cost nothing until you need it.

One sentence to remember

A skill is a procedure, stored as text, that the agent reads only when the task calls for it.

Slash commands are names you type

A slash command is what it sounds like. Type / at the start of an empty prompt and a list appears; some names are built in (/help, /status), others are saved packs. The boundary is blurry in Claude Code: its documentation states that custom commands have been merged into skills, so a file at .claude/commands/deploy.md and a folder at .claude/skills/deploy/SKILL.md both create /deploy.[1]

So "run the deploy command" means: type /, pick the name, and the saved instructions arrive with the turn. Spelling differs by tool; the tabs give the verified forms.

Skills follow the open Agent Skills standard. You invoke one directly with /skill-name, or let Claude load it when your request matches the description.[1] Personal skills live at ~/.claude/skills/<name>/SKILL.md and apply to every project; project skills live at .claude/skills/<name>/SKILL.md and can be committed so the whole team gets them.[1]

To see the list, type / at the start of a prompt — the shortcut table labels that row Command or skill.[4]

Codex can start a skill when your task matches its description, or explicitly: run /skills to browse and pick one, or type $ to mention a skill by name.[3] Project skills are read from .agents/skills in your working folder up to the repository root, and personal skills from ~/.agents/skills.[3]

/presets is the neighbouring idea: Save and run prompts or slash commands in numbered slots.[5] Use a preset for a prompt you retype; use a skill when the procedure needs its own files and a description.

omp loads a skill when your request matches its description, with no special syntax. To require one, use /skill:<name>, for example /skill:postgres Review migrations/042_add_status.sql for lock risk.[7] Skills live at ~/.omp/agent/skills/<name>/SKILL.md for every project, or .omp/skills/<name>/SKILL.md inside one repository.[7]

/extensions opens a list where each skill shows its description, scope and source path, so you can switch one off. omp's docs are written only by its own authors; check surprising details there.

@-mentions point at a file

The third habit is smaller and used far more often. When you want the agent to look at a particular file, type @ and start writing its name. Claude Code's shortcut table calls this a File path mention and says it will Trigger file path autocomplete.[4] In omp, omp reads an @path mention into the turn automatically.[8] In Codex you can do the same with /mention src/lib/api.ts[5], and its prompting guidance tells you to say which files, folders, docs, examples, or errors matter.[6]

An @-mention attaches material; it does not explain why. omp warns that a path by itself supplies context but not intent.[8] "Look at @index.html" is weaker than "the heading in @index.html overlaps the button on a narrow window".

Recall before you read on

Without scrolling up: what does a skill add that an @-mention does not, and what does an @-mention add that a skill does not?

A skill adds a procedure — a saved set of steps and rules, loaded by name or by matching your request. An @-mention adds material — the actual contents of one file, for this turn. You often want both, and the material alone never states what you want done with it.

What a pack cannot do

A skill is instructions, not a permission. omp's page is explicit: a skill does not add permissions or an executable tool by itself, and a playbook may instruct the agent to run commands using the session's existing permissions.[7] Your approval prompts still stand between the agent and your files, so keep them on. A skill that says "deploy without asking" does not get to skip that gate. It asks the agent to try, nothing more.

The second limit is trust. Skills are discovered from the project folder, so a repository you open can contribute instructions.[7] omp's rule is Treat a skill like code: inspect SKILL.md and any scripts beside it before enabling it, especially in a freshly cloned repository.[7] Unit 5 covers the wider version.

A pack, a gate, and a written procedure

A real pattern, anonymized

A user opened a session with one sentence: their app felt clunky, and a beginner would struggle to move around it. They did not describe a fix. Instead they started a saved interview pack, which required the agent to inspect the app first and then ask numbered questions, each with a recommended answer. Twenty-six questions followed; the user answered most of them with "yes to all" and corrected three.

Next they started a research pack, which produced a short note on comparable interfaces with sources, saved in the project. For the build, they used a third pack deliberately marked as human-triggered: the agent could not start it on its own. Typing its name was the "go".

The point is not that you need three packs. A name can carry a whole way of working, and the same mechanism can hold a gate. All three tools can keep a skill out of automatic reach: Claude Code's disable-model-invocation: true means Claude can't invoke the skill on its own;[1] Codex's allow_implicit_invocation: false turns off matching while keeping explicit $skill calls working;[3] omp's hide removes a skill from automatic matching and keeps /skill:<name> available.[7] Use that for anything that publishes, deletes, or sends.

Try it in your own project

Step 1 shows built-in names and possibly project or personal packs; the list is the honest inventory, not a promise. Step 3 should produce names with source paths, or a clear "none installed" — both are useful answers. Step 4 should mention reading the file and should separate the file's contents from your instruction. If it claims a skill you cannot find on disk, ask it to show the path; lesson 1.12 covers the rules file, which is the other place instructions hide.

Check yourself

Question 1 of 3

What does a skill add to your agent?

A skill stores a procedure in SKILL.md and loads it when needed. It changes no model, makes no backup, and holds no login.

Question 2 of 3

You type @ and pick a file. What did you just do?

An @-mention supplies material for this turn. It does not say what to do with the material, and it does not start or list anything.

Question 3 of 3

A cloned project brings its own skill. What is the safe habit?

A skill is instructions, and instructions can tell the agent to run things under your existing permissions. Read SKILL.md and its scripts first, then decide.

Ask your teacher

Unsure whether something should be a skill, a rules-file line, or a sentence you type? Ask: "Here is a procedure I repeat — should this be a skill, and what would its description say?" Paste the steps you keep retyping.
