Setup and sign-in

Install an agent, sign in, start it in the right folder, and get a page on screen.

The order that avoids trouble

  1. Install the program (any folder is fine).
  2. Open a new terminal window; the old one keeps the search list it started with.
  3. Check the version. That is the only proof the install worked.
  4. Start the agent inside a project folder and finish the browser sign-in.
Two separate jobs

Installing puts the program on disk. Signing in links work to your account and stores a credential on that machine. Install and sign-in fail differently: command not found is a PATH problem, not a login problem. See lesson 0.5.

Install (macOS/Linux, Anthropic's native installer):

curl -fsSL https://claude.ai/install.sh | bash

Check in a new window: claude --version. It prints a version plus (Claude Code).

Sign in: run claude and finish the browser login it opens. Credentials are stored, so later sessions skip the browser. Use /login to switch accounts, /logout to remove the stored credential.

Start in a project folder: cd ~/my-app, then claude. The session's working folder should be the one you meant.

First prompt: use the walkthrough prompt below; approve the write, then the server command.

Approval mode: claude --permission-mode manual stops before edits and commands. Shift+Tab cycles modes during a session; the name shows in the status area. Auto mode is the default from v2.1.283, so check it.

Settings: ~/.claude/settings.json holds the machine default under permissions; the project rules file is CLAUDE.md.

Install (macOS/Linux):

curl -fsSL https://chatgpt.com/codex/install.sh | sh

Check: codex --version prints a line beginning codex-cli and a version number.

Sign in: the first run asks you to choose Sign in with ChatGPT or another listed method. Follow the prompts. codex logout removes the stored credential.

Start in a project folder: cd ~/my-app, then codex. The CLI starts in the folder you launched it from.

First prompt: paste the walkthrough prompt below; approve the write and the server command.

Approval mode: in a version-controlled folder the default pairs the workspace-write sandbox with on-request approvals; network access is off by default. /permissions shows and changes the settings inside a session. OpenAI's own advice for newcomers is to start with the default permissions.

Settings: the project rules file is AGENTS.md at the repository root. The machine-wide config file location is not covered by this course — check the vendor page.

Install (its own shell installer):

curl -fsSL https://omp.sh/install | sh

Check: omp --version. If the shell cannot find omp, follow the PATH line the installer printed, open a new terminal, and try again.

Sign in: the first launch opens a setup wizard. Keep the Sign in tab, choose your provider, press Enter, and finish in the browser; then pick a model. /login reopens sign-in for OAuth users; /logout signs out. The local database is not encrypted at rest.

Start in a project folder: cd my-project, then omp. Bare omp opens the interactive terminal UI.

First prompt: paste the walkthrough prompt below; watch the approvals.

Approval mode: change it, because the built-in default is yolo. Use omp --approval-mode write for one session, or set it permanently (next line). Check with omp config get tools.approvalMode.

Settings: ~/.omp/agent/config.yml, with tools: approvalMode: write. The project rules file is AGENTS.md at the repository root; user-wide rules can live in ~/.omp/agent/AGENTS.md.

Your tab choice is remembered; the names differ, the loop does not. See lesson 0.2.

No prompt while a server runs is normal, not a freeze; Ctrl+C stops it. A returning prompt proves the program ended, not that it worked. Full lesson: 0.4.

First page in sixty seconds

  1. Make a folder and enter it: mkdir ~/my-first-page && cd ~/my-first-page. Run pwd to confirm.
  2. Start your agent from inside that folder: claude, codex or omp.
  3. Paste this prompt: 
    Build a single web page in this folder. It should show a big heading that says "Hello from my first page" and one sentence under it saying today's date. Keep it to one HTML file with no frameworks or build step.

Then start it on a local server and open it in my browser so I can see it. Tell me the exact address you opened.
  4. Approve two things: writing one file, then running one command. Read each prompt; deny anything that reaches outside this folder.
  5. Read the address it prints, usually http://localhost:8000. localhost means this computer, so only you can open it; 8000 is the port, a numbered doorway on that computer. Your number may differ — trust the printed address.
  6. Change one visible thing: ask it to change the heading, then reload the tab. Stop the server with Ctrl+C; the address then stops answering, which is expected.
Why serve it?

Double-clicking gives a file:// address and can block linked files. A served page behaves like the one you will publish. See lesson 0.7 and 0.8.

Setup checklist

  • The version command prints a number in a new window.
  • Sign-in finished in the browser.
  • The agent's first message names the same folder as pwd.
  • Approvals are on; you can name the mode.
  • A page loads at a localhost address you can read.
  • On a shared machine, sign out.
