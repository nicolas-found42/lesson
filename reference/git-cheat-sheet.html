Git cheat sheet

What each git command does, and what to do when one goes wrong.

Save a checkpoint

CommandPlain EnglishTaught in
git add <file>Pick that file's current content for the next commit.3.4
git commit -m "..."Record staged changes as a snapshot with one message line.3.4
git commit -aStage every changed tracked file, then commit; new files are skipped.3.4
git add -AStage everything, including files git has never seen.3.4
Careful

git commit -a and git add -A sweep in work you did not choose: unfinished edits, scratch files, a settings file holding a key. Check git status --short and git diff --staged first.

Branches

CommandPlain EnglishTaught in
git branchList local branches; the asterisk marks the one checked out.3.5
git switch -c add-searchCreate a branch and move to it in one step.3.5
git switch mainChange the files in the folder to main's snapshot.3.5
git branch -d add-searchDelete a branch git believes is already merged.3.14
git branch -m master mainRename the current local branch; the server is unchanged.3.14

-D deletes even when git says the branch is not merged — usual after a squash merge. Confirm the work is on main first.

Combine work

CommandPlain EnglishTaught in
git merge add-searchJoin that branch into the current one with a merge commit.3.8
git merge --squash add-searchApply its changes without committing; you commit the result.3.8
git pullFetch the remote's commits, then merge them into your branch.3.6
git fetch --pruneUpdate remote-tracking names; drop names for branches deleted on the server.3.11
git merge --abortBack out of a conflicted merge; restore the pre-merge state.3.9

A conflict leaves markers in the file: edit to the text you want, delete them, git add the file, then git commit or git merge --continue. A squash merge does not make git consider the old branch merged.

Undo

CommandPlain EnglishTaught in
git restore --staged <file>Unpick a file for the next commit; the edit on disk stays.3.4
git revert --no-edit HEADAdd a new commit that cancels the last one; history keeps both.3.11
git reset --hard HEAD~1Move the branch back one commit; overwrite files to match.3.11
git reflogWhere this repository's branch tips used to point.3.11
git push --force-with-leaseReplace the remote branch only if it is where you last saw it.3.11
Danger

git reset --hard destroys uncommitted edits for good, because no commit recorded them. git push --force can make the server lose commits other people hold; --force-with-lease is narrower but still rewrites history. Keep both off shared branches unless you mean it.

Two checkouts at once

CommandPlain EnglishTaught in
git worktree add ../my-app-experiment -b experimentMake a second folder for a new branch, sharing one history.3.10
git worktree listWhich folders are checked out, and on which branch.3.10
git worktree remove <path>Remove a clean worktree; the branch and its commits survive.3.10

One branch, one worktree. Run git worktree list before blaming a missing edit; the agent may have used the other folder.

Ignore files

CommandPlain EnglishTaught in
.gitignoreOne pattern per line: .env, node_modules/, build output, big files.3.3
git check-ignore -v <path>Which pattern excludes that path, and on which line.3.3
git rm --cached .envUntrack a file but keep it on disk; then ignore it.3.3

An ignore rule does not affect already-tracked files, and the old commit still holds the secret. Rotate a leaked key first, then untrack it.

Remote and push

CommandPlain EnglishTaught in
git remote -vThe remote names and URLs this folder has.3.6
git remote add origin REMOTE-URLSave a name for another copy of the repository.3.6
git push -u origin mainSend main and make later pushes need no arguments.3.6
git status -sbShows ahead or behind: is a push pending?3.6
git push origin --delete featureDelete that branch on the server.3.14

A push copies commits, never uncommitted edits. 403 means refused; 404 may mean the repository is missing or that you lack access (3.12).

After a mistake

  • Ask one question first: have these commits been pushed or merged? If yes, git revert. If they never left your machine, a reset is private and allowed — with the danger above in mind.
  • A branch "still exists" is a memory until you fetch. Run git fetch --prune, then git branch -r; names of deleted server branches disappear.
  • Recover a dropped commit with git reflog, then git reset --hard HEAD@{1}. It cannot restore an edit you never committed.
Remember

An agent's "done" is a claim. Read git status --short and the log yourself, and compare the live result (2.2).
