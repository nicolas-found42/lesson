Reference card

Glossary

The course's working vocabulary, one line each, with the lesson that teaches it.

Grouped by first letter, not by unit. Near-synonyms are listed in brackets; the definition is the course's own.

A

Absolute URL (absolute vs relative path, relative link, subpath): a URL with scheme and host, like an absolute path measured from the disk's top; a relative link resolves against the page, and a project site lives at a subpath. Taught in lesson 0.3.

Acceptance criteria (observable check, done when, evidence (of done)): pass-or-fail checks for one change, written before work starts; evidence is a rerunnable result. Taught in lesson 4.1.

Access token (refresh token, token expiry, re-login (re-authentication), organization re-login policy, credential store): the short-lived credential sent with each request; a refresh token gets a new one, and an admin policy can force re-login. Taught in lesson 8.6.

Accessibility (target size, keyboard accessibility, focus indicator, reduced motion): an app that works for people who see, move or hear differently; controls need reachable targets, visible focus and respect for reduced motion. Taught in lesson 8.20.

Agent loop (coding agent, context, turn): the gather–act–verify cycle a coding agent repeats; one turn from you can trigger many actions, and context is what it can see. Taught in lesson 0.1.

Agent shell (harness): the vendor-specific program around the model — start command, interface, settings, rules-file name. Taught in lesson 0.2.

Amendment (batch yes, read-back, amendment inside the go): a numbered change inside a one-line acceptance of every recommendation; the agent reads decisions back before editing. Taught in lesson 1.5.

Asset (license (file), Creative Commons license, reverse engineering): a non-code file someone owns; a license states what others may do, Creative Commons letters spell the permission. Taught in lesson 8.18.

Auto-fix (auto-merge, review bot, pending (check), required check, late comment): standing permission to react to failing checks or review comments, never to merge; a late comment needs a new pull request. Taught in lesson 9.4.

B

Background process (polling, completion notification, timeout): a program still running after control returns; poll it or wait for a completion notification, under a timeout. Taught in lesson 5.9.

Backend (serverless function, database, application server): the parts visitors never see — hosting, functions, data; a serverless function runs per request, and a database outlives a visit. Taught in lesson 8.9.

Branch (default branch, feature branch, Switch (checkout)): a movable label on one commit; switching updates the folder to match another branch. Taught in lesson 3.5.

Branch protection rule (protected branch, bypass setting, ruleset, GH006): a setting that refuses pushes or merges unless requirements such as a pull request and passing checks are met. Taught in lesson 3.15.

Budget (attempt, spend limit, hard cap): a measurable limit on time, attempts or dollars, plus the rule for returning control; a hard cap is enforced by software. Taught in lesson 4.4.

Build step (source, build output, build output folder, base path): a program that turns source into a fresh folder of deployable files; the base path is the address prefix in their links. Taught in lesson 6.2.

C

Capstone (project card, fallback example, shippable idea): the final project, run end to end on an idea you chose; a project card records idea, audience and finish line. Taught in lesson 7.1.

Changelog (release notes, deprecation page): the provider's own dated list of changes and end-of-life notices, and the authoritative source on third-party churn. Taught in lesson 8.15.

CI (continuous integration (CI), workflow (GitHub Actions workflow), trigger (event), job, runner, action (GitHub Action), workflow run, status check, Check (status check), skipped (test or check), flaky (check)): checks run on a shared server at every push; a trigger starts a job on a fresh runner, and its status can be pending, passing, failing, skipped or flaky. Taught in lesson 2.12.

Client ID (client secret, scope, redirect URI, consent screen): the public name of a registered app; the secret stays server-side, scopes are requested permissions, and the redirect URI is the registered return address. Taught in lesson 8.7.

Commit (checkpoint, save point, snapshot, version control, history, commit message, commit title): a recorded snapshot of all tracked files with a message and a parent link; history is the chain of them. Taught in lesson 3.1.

Conflicting requirements (trade-off): requirements that cannot all hold; name the trade-off and let the human choose. Taught in lesson 4.6.

Container (image, volume, port): a runnable instance of a read-only image; changes vanish unless kept in a volume, and publishing a port lets the host reach it. Taught in lesson 8.12.

Context window (compaction, resume, fork, handoff): the limited space holding what the agent can attend to; compaction summarizes older turns, and resume, fork or a handoff carry work forward. Taught in lesson 5.1.

CORS (Cross-Origin Resource Sharing, origin, same-origin policy, preflight request, Access-Control-Allow-Origin): headers naming which origins may read a response; the same-origin policy is the rule, and a preflight checks permission first. Taught in lesson 8.8.

D

Definition of done (done when, acceptance criteria, evidence of done): what must be true for work to count as finished, ideally checkable by a command. Taught in lesson 1.13.

Dependency (timeout, output limit, backoff (exponential backoff), JSON shape, fallback): something needed at runtime but not controlled; give calls a timeout and output limit, retry with backoff, validate the JSON shape and plan a fallback. Taught in lesson 8.16.

Deploy (publish, deployment run, live site, cache, verification): one attempt by the host to build and serve files; the live site is the URL returning the new content, and a stale cache can show the old. Taught in lesson 6.6.

Deploy blocker (secret manager, environment secret, empty string): anything stopping a new version going live, usually a missing secret; an unset expression yields a silent empty string. Taught in lesson 8.14.

Deprecation (third-party churn, HTTP 404 Not Found, HTTP 410 Gone, dead link / link rot, changelog): a provider's dated end-of-life notice; 404 means not found now, 410 permanently gone, and the changelog is authoritative. Taught in lesson 8.15.

Derail (interrupt, parked branch, fresh goal, draft pull request): a run drifted from the goal; stop it, commit, park the work, restart with a smaller fresh goal. Taught in lesson 4.10.

Desktop app (of an agent) (plan checklist, button reply, permission card): the windowed interface, where steps show as a checklist and approvals as cards. Taught in lesson 5.11.

Domain (registrar, DNS (Domain Name System), DNS record, apex domain, subdomain): the site's readable address; a registrar sells it, DNS maps names to servers, and an apex domain has no prefix. Taught in lesson 6.10.

Done (as a claim) (claim, verification, not verified): the agent's report that it finished, which is not proof; verification looks at real evidence, and "not verified" names what was skipped. Taught in lesson 2.2.

E

Emulator (production (backend), rehearsal room / stage (metaphor)): a local imitation of a hosted backend, safe to break; production holds real data, quotas and billing. Taught in lesson 8.10.

Environment variable (.env, .env.example): a named value read at runtime and kept out of code; .env holds real values and is git-ignored, while .env.example commits the names only. Taught in lesson 8.2.

Evidence (screenshot, screenshot as evidence, black frame, negative control, frontmost window, screen-recording permission): an artifact that would differ if the work were wrong; a black frame means the capture or app failed, so test a known-good negative control. Taught in lesson 2.8.

Exit code (exit status, one-command gate, package script, Makefile): the number a command returns, zero meaning success; a gate puts every check behind one. Taught in lesson 2.3.

F

Failure mode (retrospective): a named recurring way runs go wrong; a retrospective matches each problem to one and writes a prevention rule. Taught in lesson 7.3.

First-time user (first-time-user walk, think-aloud, usability problem): someone without the builder's memory; a walk with think-aloud exposes usability problems where expectation and screen disagree. Taught in lesson 2.13.

Fixture (test double, mock, stub, fake, wire test, live test): a saved sample input or output; a stub returns canned answers, a mock records calls, a fake is a working simplification, a wire test uses the real protocol, and a live test the real service. Taught in lesson 8.13.

Flaky test (vacuous check, todo/skipped test, AI-as-judge): a test that passes and fails on unchanged code; a vacuous check never compares, and AI grading carries noise. Taught in lesson 2.11.

Fork (upstream repository, personal access token, 403 Forbidden, 404 Not Found): a separate repo connected to the original; GitHub access uses a personal access token, and 403 or 404 can mean insufficient permission. Taught in lesson 3.12.

Force push (force with lease, reset, reflog): a push that replaces remote history; --force-with-lease refuses if the remote moved, and the reflog can recover commits. Taught in lesson 3.11.

Frames per second (fps) (benchmark, bottleneck, parallel worker, profiling): images drawn each second; a benchmark measures repeatably and profiling finds the bottleneck. Taught in lesson 8.19.

Free plan (usage limit (guardrail), credits, bandwidth (data transfer), size limit): a host's no-cost tier with published caps on builds, traffic and files. Taught in lesson 6.8.

G

GitHub Pages (user site, project site): free static hosting; a user site lives at owner.github.io, a project site at owner.github.io/repository. Taught in lesson 6.3.

Glossary (re-pitch, output style): plain-word definitions kept where both of you can read them; a re-pitch asks again in a different form, and an output style sets tone. Taught in lesson 1.3.

Goal (audience, method, constraint): the outcome that should exist at the end and who it serves; naming only the method leaves the goal to guesswork. Taught in lesson 1.1.

Go (the gate) (plan, plan mode, edit, blast radius, gate (human "go")): your approval between a written plan and the first edit; plan mode stays read-only while drafting. Taught in lesson 1.7.

Goodhart's law (proxy, reward hacking, specification gaming, negative control): optimizing a measure stops it tracking the outcome; a proxy is the stand-in, and reward hacking improves it while harming the goal. Taught in lesson 4.7.

H

Host (web host) (hosting, static site, dynamic site, client-side code, web server, published site): a service serving files to browsers; a static site is served as stored, a dynamic site generates responses. Taught in lesson 6.1.

HTML (CSS, JavaScript, stylesheet, web page): the structural language of a page; CSS styles it, JavaScript adds behaviour, and the page is a bundle of files that must find each other. Taught in lesson 0.8.

Human-only step (runbook, attestation): a step needing your identity or word; the runbook lists them, and an attestation is a statement only you can make. Taught in lesson 5.10.

I

In-folder question (outside-the-folder question, pointer answer, check instead of guess): one answerable from the project; an outside question needs your fact, a pointer sends the agent to the path, and an unanswerable one becomes a check. Taught in lesson 4.12.

Install (sign in, version check, credential, PATH): copying the program so its command exists; sign-in stores a credential, and a version check proves PATH finds it. Taught in lesson 0.5.

Integration branch (per-ticket branch): a holding branch collecting several tickets before the batch merges to main; a per-ticket branch carries one. Taught in lesson 9.2.

Interview (numbered reply, recommended answer, recommendation, override, product intent, mechanism, recommendation test, spec): numbered questions with one recommendation each; you reply by number, override product decisions, and the record becomes the spec. Taught in lesson 1.4.

L

Local server (localhost, port, address, start and open, preview, refresh, look): a program serving a folder at an address such as localhost:8000; refresh re-fetches, and "look" is your own check. Taught in lesson 0.7.

Log (telemetry, structured log, log level, diagnosable): a timestamped message about behaviour; structured logs use named fields, and levels rank severity so a bug is diagnosable. Taught in lesson 2.9.

M

Merge (merge commit, squash merge, merged, base branch, head branch, rebase, cherry-pick): bringing a branch's commits into another; a merge commit records the join, and squash makes one new commit. Taught in lesson 3.8.

Merge conflict (conflict marker, merge --abort): a pause where two branches changed the same place differently; Git writes both versions between conflict markers and waits. Taught in lesson 3.9.

Model (effort (reasoning effort), model switch, cheaper-for-building pattern): the reasoning brain; effort controls how long it thinks, and a model switch changes it mid-session. Taught in lesson 5.6.

O

Orient first (read-only question, plan mode, map): read what exists before changing anything; ask read-only, use plan mode, and keep the map of files and risks. Taught in lesson 1.2.

Outcome-sized prompt (micro-managing, vague prompt): a request naming one checkable result and leaving steps to the agent; a vague prompt is safe only where the repo defines "works". Taught in lesson 1.13.

P

Permission mode (approval prompt, auto mode / bypass / yolo, sandbox, defense in depth): the setting deciding which actions run without asking; a sandbox bounds the damage. Taught in lesson 0.6.

Plan (reference, baseline, copy list, skip list, bar): a written proposal of steps and checks; a reference is the model to match, a baseline your own accepted minimum. Taught in lesson 1.8.

Project folder (file path, file extension, working directory, path): the folder you point an agent at; paths route to files, and relative paths resolve from the working directory. Taught in lesson 0.3.

Prompt caching (token, cache hit / cache miss, cache lifetime (TTL)): a provider storing the processed start of a request for cheaper reuse; a cache hit reuses it, a miss reprocesses it, and the TTL is how long it survives. Taught in lesson 5.2.

Prompt injection (untrusted content): instructions hidden in text an agent reads, hoping it obeys them; anything you did not write is data, not orders. Taught in lesson 5.7.

Provenance (unit, evidence status): where a value came from and when; its unit is its scale, and evidence status says measured, sourced, estimated or unknown. Taught in lesson 8.17.

Pull request (PR) (base branch, head branch, draft pull request, merge box): a host page proposing to merge a head branch into a base branch; a draft cannot merge yet. Taught in lesson 3.7.

Push (remote, origin, tracking branch, remote-tracking branch, remote-tracking reference, upstream branch, prune): copying commits to a remote; a tracking branch records its counterpart, and prune drops references to deleted branches. Taught in lesson 3.6.

Q

Question cap (over-asking, blocker): an agreed maximum on interview rounds before the agent summarizes decisions and unresolved blockers. Taught in lesson 4.11.

R

Rate limit (HTTP 429, HTTP 402, credits, spend cap): a provider's request cap per time window, answered with HTTP 429; 402 often signals billing, and a spend cap rejects further calls. Taught in lesson 8.4.

Real browser (simulated environment, headless browser, rendering, layout): an actual browser showing the page; a simulated environment never paints, and layout depends on window size. Taught in lesson 2.7.

README (repository description, website field (homepage), about box, topic): the repo's front page file; description, website and topics fill the About box. Taught in lesson 6.7.

Regression (regression test, failing test first, red / green, fails for the wrong reason): a feature that worked and stopped; its test fails first on the broken version and passes after the fix. Taught in lesson 2.4.

Release (raw file URL, pinned commit): a repo page with downloadable files; a raw URL serves bytes, and a pinned commit keeps them unchanged. Taught in lesson 6.4.

Repository (repo) (working tree, .gitignore, ignored file, untrack, generated file): the project folder plus its history; .gitignore excludes patterns, and untrack removes a file from the index only. Taught in lesson 3.2.

Revert (rollback, main, live site): a new commit cancelling an earlier change; a site rollback republishes a working version. Taught in lesson 6.9.

Root cause (symptom, workaround): the mechanism producing a failure; the symptom is its sign, and a workaround avoids it without repairing it. Taught in lesson 4.5.

Rules file (project rules file, standing instruction, checkable rule, loaded instruction source): a plain-text file read at session start, named CLAUDE.md or AGENTS.md; it holds standing, checkable instructions. Taught in lesson 1.12.

S

Scheduler (agent as scheduler) (orchestration, meta-prompt, done-when (finish line)): the role where you give goal and finish line and the agent sequences the work; a meta-prompt asks it to critique your prompting. Taught in lesson 9.6.

Scope (personal access token, OAuth scope): a named access limit on a token, such as a personal access token's permissions; an OAuth scope is one requested permission. Taught in lesson 3.12.

Scope creep (scope ladder, rung, promotion, scope cut, deferral note, out-of-scope line): work growing through small additions nobody chose; a deliberate cut is recorded in a deferral note. Taught in lesson 4.2.

Secret (API key, token (login), connection string, private key file, rotate (a key), print (a secret), credential store, Git history): a value that lets its holder act as you; a credential store keeps tokens locally, so never print or commit one, and rotate if leaked — history keeps it. Taught in lesson 8.1.

Session (resume, fork, handoff, handoff doc, fresh session): one saved run tied to a working directory; resume reopens it, fork branches it, and a handoff doc lets a fresh session continue. Taught in lesson 0.2.

Skill (agent skill) (slash command, @-mention, skill description): a folder of instructions loaded when a request matches its description; slash commands start saved prompts. Taught in lesson 1.11.

Source of truth (stale claim, invented claim, unverified claim): the authoritative place a claim is checked against; a stale claim described the past, and an unverified claim was never checked. Taught in lesson 5.8.

Spec (ticket, dependency graph, frontier, blocked): one document describing the app; tickets split it into run-sized pieces, arrows form the dependency graph, and the frontier is unfinished tickets with finished dependencies. Taught in lesson 9.1.

Staging area (stage (a file), staged, commit all, uncommitted change, modified, untracked, uncommitted work): what the next commit records; a modified file is tracked and edited, an untracked one was never committed. Taught in lesson 3.2.

Static check (formatter, linter, lint rule, type, type checker): a tool reading source without running it; a formatter rewrites appearance, a linter reports patterns, and a type checker verifies kinds. Taught in lesson 2.5.

Stop condition (boundary, "and stop there", present-tense stop, persistent goal, goal mode, persistent objective): where a run ends and what it must not start; the finish line and boundary are its halves, and a persistent goal keeps checking one condition across turns. Taught in lesson 4.3.

Subagent (parent agent, independent reviewer, read-only contract, cross-checking, review finding, advisory, review scope): a helper with its own context; a read-only contract forbids edits, and findings are advisory within the review scope. Taught in lesson 2.10.

Swarm research (report, reconciliation, contradiction, unverified claim): one question sent to helpers on disjoint slices, then reports merged; reconciliation returns to the source when they contradict. Taught in lesson 9.5.

T

Terminal (shell, command, prompt (terminal), CLI (command-line interface)): the window where you type a command; the shell runs it, the prompt is the ready marker. Taught in lesson 0.4.

Test (assertion, test runner, pass / fail / skipped): a stored check comparing real and expected; an assertion compares, the runner reports, and a skipped test proves nothing. Taught in lesson 2.3.

Third-party churn (deprecation, dead link, link rot): changes by services you do not run — deprecations, removed endpoints, moved or deleted docs — that break an app depending on the old behavior. Taught in lesson 8.15.

Third-party service (data retention, zero data retention (ZDR), model training opt-out, egress): an outside company receiving your data; know its retention, ZDR and training policy, and what egress leaves. Taught in lesson 8.5.

Tool call (read-before-edit, sandbox, tool output): one use of one tool, whose output is what the agent perceives next; edits apply only to text read first. Taught in lesson 5.3.

Triage (report, steps to reproduce, console, network panel): reading a report before changing code; reproducible steps make it testable, and the console and network panel show the rest. Taught in lesson 2.14.

Triage prompt (diagnosis, recommendation, stale branch): a saved read-only prompt diagnosing state and ranking recommendations with exact commands; a stale branch is merged or abandoned work. Taught in lesson 9.8.

Turn (queue (a message), interrupt, continue, state question): one message plus the agent's whole response; queue adds without cancelling, interrupt stops the current action. Taught in lesson 1.3.

U

Unsupervised run (evidence checkpoint, progress log): a long task done while you are away; demand an early evidence checkpoint and a progress log. Taught in lesson 4.9.

W

Workload identity (OIDC token (id-token), trust relationship (OIDC trust), short-lived token): a CI job logging in with a short-lived signed token instead of a key; the provider checks it against a trust rule. Taught in lesson 8.11.

Worktree (linked worktree, main worktree, checkout, working directory (of an agent), race condition, parallel agents, build output folder): a second folder checked out to another branch; parallel agents each need one, or they race on the same build output. Taught in lesson 3.10.
